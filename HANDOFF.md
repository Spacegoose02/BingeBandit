## Start here

### What this is

BingeBandit is a self-hosted media server meant to replace Plex, Jellyfin, Dispatcharr and ErsatzTV in one app: libraries, live TV with a guide and DVR, custom channels, and apps for browsers, Windows, Android TV / Fire TV / phones and Roku. It's pre-1.0 and runs at home and on family members' TVs. Michael (GitHub `Spacegoose02`) owns it and makes the product calls; when this log says "Michael chose", that's a decision to keep unless he changes it.

### The five-minute version

```sh
./build.sh && ./dist/bingebandit          # or .\build.ps1 on Windows; http://localhost:8484
cd server && go vet ./... && go test ./... # what CI runs, plus gofmt -l . and the web build
cd server && go run ./cmd/fakeiptv         # a fake IPTV provider; more fakes in DEVELOPMENT.md
```

Before changing code, know these:

- **Migrations are append-only and hashed.** Add a new one at the end of `store/schema.go`; `migrate_test.go` fails if a shipped one changes (v0.22.0 broke upgrades that way). Prefer prefs or settings rows when they'll do.
- **Every user-facing item query goes through `store.visible`** (library access, profiles and kid mode). Hidden things answer 404.
- **Three clients share the API:** web (`web/src/types.ts`, which the Windows app shows full screen), TV app (`apps/tv/src/types.ts`) and Roku. Older installed apps don't send new fields, so the server must keep stored values when a field is missing.
- **The TV app is mostly tested by typechecking.** Most TV work since the phone layouts was never run on a device; say so in the log when that's the case, and say what you did try.
- **Plugins are separate binaries** under `server/plugins/`, listed in `build.sh`, `build.ps1`, the Dockerfile and `release.yml`. A new bundled plugin goes in all four.

## End credits count as watched (2026-11-14, no migration)

Michael stopped Below S1 E1 in its end credits (about 93%, converting in the web player) and it stayed on Continue Watching.

## Damaged database no longer says every season is missing; Optimize database repairs damaged indexes (2026-11-14, no migration)

Michael saw "Seasons 1, 2, … 29 aren't here yet" under South Park with every season in the library. His server's log was full of `database disk image is malformed (11)` (Cinemask collections, custom channels, the ratings task): the SQLite file is damaged. With planner statistics the season count reads `items_library_kind`, so it failed, and `ShowSeasons` swallowed the error and returned an empty map, which every caller took as "nothing here". Every show on his server read the same way.

- **`store.ShowSeasons`** now returns `(map, error)`, checks `rows.Err()` and fails on a bad row. `titleInfo` leaves `seasons` out (and logs) when it can't count, so the web's missing-seasons panel and the TV's Request button stay hidden; `serverCovers` lets the request through; `offerNextSeason` and `RequestCovered` do nothing.
- **Optimize database** (`store.Optimize`) starts with `PRAGMA integrity_check(5)`. On damage it checks every table reads in full `NOT INDEXED` (if not: error, restore a backup, nothing changed), then `rebuildIndexes`: drop the index rows from `sqlite_schema` with `writable_schema` (REINDEX and DROP INDEX read the damaged pages and fail), bump `schema_version`, VACUUM (copies only tables, leaves the damaged pages behind), and create the indexes again from their saved SQL. A second integrity check must pass; the result starts "repaired damaged indexes".
- **Tested:** `go test ./...` with new `TestDamagedIndexIsReportedAndRepaired` (overwrites the items indexes' root pages in a real file). Not tried on Michael's database; if his damage is in a table, the task says to restore a backup.

## Bigger items from the TV and server review (2026-11-13, no migration)

The rest of the review Michael picked ("all"), after the quick wins below. Testing on his own TV boxes (item 5) is still to do.

- **What the box can play** (`android/…/VideoSupportModule.kt`, `src/videoSupport.ts`): `capabilities()` lists the box's video decoders (`maxHeight` 2160/1080/720, `tenBit` from the profile levels; software decoders count to 1080p only) and the screen's HDR types. `canDirectPlay` now also checks `videoPlayable` (codec, height, bit depth, HDR the screen shows), so a file the box can't show converts up front instead of after the black-screen check or the 20 s watchdog (both still there). An older app build or a box that won't answer counts as able, as before. `MediaFile.bitDepth` and the video stream's `range` are now in the TV types.
- **HDR on a screen without it** converts with `tonemap: true` (`stream.Options.Tonemap`), even when the admin turned tone mapping off. On the CPU, tone mapping now scales down first (`scale=-2:H` before the `zscale` chain) and stops at 1080p (`maxTonemapHeight`), so a 4K HDR file converts in real time; that cap also applies to the web player. GPU tone mapping (tonemap_vaapi, libplacebo) isn't done: it needs a test on real hardware first.
- **Frame rate matching**: `matchFrameRate(fps)` picks a display mode at the current resolution whose refresh rate is the frame rate or a whole multiple and sets the window's `preferredDisplayModeId`; the player waits 1.5 s for the TV to switch, and `resetFrameRate` hands it back 3 s after the player closes (so the next episode doesn't switch twice). Settings → "Match the TV to the video's frame rate", on by default, TV only. **Server:** `Stream.FrameRate` from ffprobe's `avg_frame_rate`/`r_frame_rate`; files probed before get it with one quick ffprobe the first time their details are opened (`fillFrameRate`, saved with `UpdateStreams`). Multi-View and Live TV don't switch.
- **Conversions at once** (`stream.Manager.conversionLimit`, setting `max_video_conversions`, Settings → Transcoding): 0 (default) means a quarter of the CPU's threads, at least 2, when encoding with libx264, and no limit with a hardware encoder. Past it `Start` returns `BusyError` and the API answers 429 with a message the players show. Copies, finished conversions and replacing a session (seeking) don't count. Live TV's conversions aren't counted.
- **Instant Home**: `api.ts` keeps `/api/home`, `/api/libraries` and `/api/me/prefs` on the device per server and profile (`persist`, `restoreCache`). When nobody has to pick a profile (`profileChosen`, or `bb.noPicker:<server>` from the last start), `App.tsx` opens on that Home at once and checks `/api/me` behind it (a 401 still goes to sign-in). **Server:** Home waits at most `homeTMDBWait` (0.3 s) for a "Because you…" row; the TMDB lookup carries on and is remembered for the next load.
- **On the onn box (2026-11-13, over adb, Google TV 14, 1080p SDR TV):** test builds 0.51.1–0.51.5 from this branch, signed with the repo's debug key like the installed 0.51.0. Cold start to Home with focus: 9.3 s with the v0.51.0 code, 4.8 s with the kept Home, 2.4 s once Home's rows were memoized and drawn three first then two a frame (`HomeRows`, `FIRST_ROWS`). The rest of start-up is ~1.2 s (JS start and module loading). 4K HEVC and 1080p files played direct, about 3–4 s from OK to moving picture; Settings shows the frame rate row; the refresh rate didn't change because the server hadn't been updated to send frame rates. **The box runs 0.51.5, so the next release must be newer than that** for it to install over it.

## Audio out of sync: an audio timing control and gap-filling for converted audio (2026-11-05, no migration)

Michael: "sometimes the audio seems out of sync from the picture and no way to fix it on the TV app or web".

- **Root cause hunt:** reproduced with real ffmpeg (6.1) what the transcoder does when seeking, switching tracks and copying video with converted audio: the timestamps stay correct in every case (a copied picture starts at the keyframe before the seek point, the sound at the point itself, and they line up by timestamp). The one weakness found: converted audio kept any gaps in the source (TV recordings, IPTV, broken muxes) as gaps in the timestamps. Browsers follow timestamps, but players that clock by the samples they've played (ExoPlayer on Android TV, Roku, Chromecast) only resync on a big jump, so small gaps add up to drift. Converted audio now goes through `aresample=async=1` in `stream.buildArgs`, the Live TV relay, custom channels and downloads, which fills gaps with silence. That's the most likely cause; not proven on a device. A file whose audio is copied (or a source that's simply muxed out of step) still needs the control below.
- **Audio timing control:** `Options.AudioDelayMs` (±`MaxAudioDelayMs` = 5000) on `POST /api/files/{id}/transcode`. `buildArgs` opens the file a second time for the audio with `-ss` and `-itsoffset`, so video and audio can both still be copied. ## Playback rides out a server restart (2026-11-02, no migration, apps only)

Michael asked whether a server restart would go unnoticed by people watching. It didn't: conversions live only in the server's memory (their folders are wiped at shutdown and start), so a restart left the web player retrying a dead stream forever, Roku and Android TV showing "Playback failed" if the server wasn't back yet, and the Windows app possibly counting a cut connection as the end of the file.

- **All players:** on an error they first check `GET /api/health`. If the server doesn't answer (or a proxy says 502/503/504), they show "Lost the server. Reconnecting…" and check again after 2, 4, 8, 15, 15… s for up to two minutes, then carry on from the same spot the same way (direct play again, or a new conversion). The two-minute window resets once playback runs again. A failed conversion request with no answer does the same.
- **Android TV / phone** (`apps/tv/src/screens/Player.tsx`): `reconnect`, `playDirect` (now shared with the quality menu; adds `?n=` so the player is rebuilt), `serverGone`. With the server up, a direct-play error on a file that had played is tried direct once more (at most once per 30 s of the file) before converting; a conversion still gets one restart as in #182.
- **Web** (`web/src/pages/Player.tsx`): `waitForServer`, `lostStream`. A fatal hls.js network error now starts a new conversion from the current spot (at most 3 times before playback runs again) instead of `startLoad()` on the dead session; a `MEDIA_ERR_NETWORK` on the video element reloads the same way.
- **Roku** (`PlayerScreen.brs`, new `reconnectTimer`): `onErrorHealth`, `lostServer`, `onReconnectHealth`, same rules as Android TV.
- **Windows** (`apps/desktop/src/mpv.js`, `web/src/pages/DesktopPlayer.tsx`): mpv gets `--stream-lavf-o=reconnect=1,reconnect_streamed=1,reconnect_on_network_error=1,reconnect_delay_max=60`, so ffmpeg reconnects from the same byte for about two minutes. If the file still ends or fails more than 2 minutes before its end after playing, `lostServer` waits for the server and reloads from there instead of marking it watched.
- **Not changed:** the server still loses conversions on restart (sessions are in memory); viewers on a conversion get a few seconds of buffering while a new one starts. Live TV players already rejoin on their own.
- **Tested:** TV `tsc` and `eslint`, web `tsc` and build, Roku `brighterscript`, desktop `npm test`. **Not tried** against a real restart on any device.

- **Web:** `components/Cast.tsx`: the TV picker (cast button on a title, and in the player, which hands over the current position and audio track and leaves), and `CastBar`, a remote along the bottom of every page (seek bar, ±, pause, Chromecast volume, stop) that polls every 2 s while casting.

## Sports: games on the right local channel, Admin → Live TV → Networks (2026-11-01, migration 52, v0.40.0)

Michael reported Sports games landing on the wrong channels: CBS games not on WDBJ, NBC not on WSLS (Roanoke locals). Cause: `findChannels` (`api/sports.go`) never used the network ESPN lists (`Game.Broadcasts`). It only looked for a guide programme near kick-off naming both teams, so a local whose guide says "SEC on CBS" never matched, while other cities' CBS stations, replays or preview shows that named the teams did, and the first six matches by channel number filled the list.

- **Migration 52:** `network_channels (network COLLATE NOCASE, channel_id → channels ON DELETE CASCADE, position)`. Store: `Networks`, `SetNetworks` (`store/networks.go`; replaces the whole mapping, drops blank names and unknown channels).
- **API** (`api/networks.go`): `GET /api/admin/live/networks` → `{networks: [{network, channels}], known}`; `PUT` takes the list and returns the same. `known` is `commonNetworks` plus every broadcast name `findChannels` has seen since start (`Server.networksSeen`), spelled as ESPN lists them.
- **Matching** (`findChannels`): for each of a game's networks with mapped channels, `carriesGame` checks the channel's guide at kick-off. It counts when there's no guide, nothing at kick-off, a programme naming either team (or the race series), or a sports programme (`isSportsProgram`: category/genres "sport" or a sports word in the title) that names no other match-up (`reMatchup`: "X at Y", "vs", "@"). If any mapped channel carries it, those are the game's channels and the guide-title search is skipped, so other cities' stations stay out. Otherwise, as before, the guide-title search (now `namesGame`). Duplicates are dropped; still at most six. This feeds the Sports page, the hub, the score bug and the "starts soon" alert link.
- **Web:** `pages/admin/Networks.tsx`, a **Networks** tab on Admin → Live TV: add a network (suggestions from `known`), add channels by typing number or name, remove either. Saves on each change. `NetworkChannels` in `types.ts`. GUIDE.md mentions it.
- **Tested:** `TestNetworkChannels` (unmapped CBS goes to another city's station; mapped CBS → WDBJ with a generic "SEC on CBS" title and the other city dropped; NBC → WSLS showing "Alabama at Georgia" falls back to the guide; a channel with no guide is trusted; non-admin PUT is 403; deleting a channel removes it from the mapping; seen networks are offered), `TestCarriesGame` (title cases), the existing sports tests, `go vet`, `go test ./internal/...`, the web build. ## Decisions made

| Decision | Why |
| --- | --- |
| Go server, single binary, web UI embedded | Simple installs on Windows, Unraid and Docker; strong at concurrent streaming |
| SQLite via `modernc.org/sqlite` (pure Go) | No CGO, so cross-compiling every OS from one CI runner just works |
| React + Vite web UI | Shares code and ideas with the planned React Native TV/phone apps |
| HLS via ffmpeg, 4-second segments, "event" playlists | Works in every browser (hls.js) and natively on Apple/Android TV |
| Accent colour teal `#2dd4bf` on a near-black UI | Fits the grey low-poly raccoon brand; distinct from Plex's amber |
